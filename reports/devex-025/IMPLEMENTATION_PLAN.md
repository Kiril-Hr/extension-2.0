## Test matrix

| Surface | Stimulus | Required evidence |
| --- | --- | --- |
| TypeScript contracts | Compile an independent consumer with strict tsc --noEmit and public imports. Cover all three directions, both content destinations, request and notify. Negative fixtures use @ts-expect-error for unknown name, wrong caller, wrong destination, mixed frame/document, wrong payload, wrong result/domain error, notification with response and incorrect sender narrowing. Include a variable union of names with a mismatched payload. | Positive programs typecheck and each intentional error is consumed. Removing a type restriction makes the corresponding negative fixture fail. |
| Adapter unit | Controlled Chrome callbacks, deterministic clocks and injected IDs. Deliver parallel requests in reverse order, unrelated envelopes, duplicate callbacks, malformed successes/errors, thrown/rejected handlers, absent receivers, expired deadlines, pre/post-send abort, teardown and late responses. | Each caller settles once with its own result. Deadline does not imply rollback. Tables/listener counts return to baseline. Invalid inputs never enter a handler. Synthetic results here concern dispatcher logic only. |
| Lifecycle | Activate two factory owners sharing one widget/service in a document. Remove one, cycle the other through 20 route changes, fail setup halfway through a group, register a colliding name, call final teardown twice. | Shared owner still receives one call. Inactive route receives none. Final owner removes native listener and every binding. A captured old disposer cannot remove a newer binding. Pending responses from old activation are discarded. Worker definitions stay live across tab teardown. |
| Popup/content to worker | In a fresh profile load the packed consumer's unpacked extension. Open packaged popup UI and two scoped pages. Invoke the same query from popup and content, and an admitted event. | Compare typed result and actual native sender metadata, verify per-handler ACL and actual business effect. Popup closure after send yields an unknown remote outcome. |
| Worker to content | Select main frame, named child frame and originating document across two tabs. Navigate the iframe to a new document before a delayed document-targeted send. Close the selected tab in flight. | Exactly the intended live frame records the request. The replacement document and other tab receive zero commands. No retries or broadcast. |
| Worker restart | Observe activated registration using CDP, stop its version, observe stopped, then send a new request from an already open tab. Separately terminate worker while a controlled command is awaiting a response. | New request wakes the worker and succeeds with a fresh boot identifier. The interrupted request settles within deadline, with one client send and no automatic replay. Demonstrate unknown execution when an effect precedes a lost reply. |
| Parallelism and timeout | Interleave at least 20 requests across two frames with different completion order. Delay one past its deadline, abort another, return one domain error, then send a fresh request. | IDs and authorized recipient match every observed effect. Last request succeeds, late completion changes no settled result and no unbounded queue remains. |
| Negative controls | In disposable fixture builds omit the background listener, remove the content binding, throw in an otherwise valid handler and supply a wrong response shape. Send a foreign marker, forged role/target, disallowed origin, extra field and oversized payload. Attempt a page-world invocation using ordinary DOM events/postMessage. | Missing endpoint gives unavailable/channelClosed or bounded timeout, present dispatcher with missing binding gives noHandler. Other outcomes are handlerFailed, invalid, forbidden or ignored according to ownership. Page actions cannot dispatch privileged work. Verify handler invocation counters, not solely returned codes. |
| Regression and Dev Reload | Build existing minimal example and typed consumer via installed devex-scripts build/dev. Change a worker handler dependency during watch, introduce a compile error, repair, reload, and send again. Inspect actual packed files and both manifests. | New worker and content generation interoperate after successful rebuild only. Existing private SPA routing, raw Chrome callbacks, React cleanup and shared DI regressions pass. Dev tools do not enter the production runner. No additional grants from enabling transport. |

## Support and approval

Target Windows 10 and Windows 11 desktop, Node 24, Webpack 5 and Chrome/Chromium MV3. Include the existing Chromium 141 Windows CI reference and current Chrome on each supported desktop OS. Identify exact tested versions, use disposable profiles and retain per-step exit codes, tarball integrity and browser diagnostics. A hosted Windows Server runner alone cannot establish both desktop configurations. Treat these as future acceptance tests. No Messaging implementation, package or browser result is claimed by this RFC.

Use the accepted addressing, deadline, admission and retry policies in [ADR-001](ADR-001.md). Resolve packaged worker and popup entry ownership, handler lifecycle behavior, sender policy, payload budget and the supported Chrome floor before public export.
